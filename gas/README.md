# Google Apps Script セットアップ手順

コンタクトフォームの送信内容を **スプレッドシートに保存** し、
**管理者へ通知メール／申込者へ自動返信メール** を送るための設定。所要 10 分程度。

---

## 1. スプレッドシートを作る

1. https://sheets.new を開く
2. ファイル名を `GK WORK 問い合わせ` などにする
3. URL から **スプレッドシート ID** を控える

   ```
   https://docs.google.com/spreadsheets/d/【ここがID】/edit
   ```

シートの見出し行はスクリプトが初回送信時に自動で作るので、手で用意する必要はない。

## 2. Apps Script プロジェクトを作る

1. スプレッドシートのメニューから **拡張機能 → Apps Script**
2. 既定の `コード.gs` の中身を全部消し、`gas/Code.gs` の内容を貼り付ける
3. 保存（⌘S）

## 3. スクリプトプロパティを設定する

左サイドバーの **⚙️ プロジェクトの設定 → スクリプト プロパティ → スクリプト プロパティを追加**

| プロパティ | 値 |
|---|---|
| `SHEET_ID` | 手順 1 で控えたスプレッドシート ID |
| `NOTIFY_EMAIL` | 通知の宛先メールアドレス（カンマ区切りで複数可） |

> ID やアドレスをコードに直書きしないのは、リポジトリに載せずに済ませるため。

## 4. 動作確認する

エディタ上部の関数プルダウンで **`testSubmit`** を選び、**実行**。

- 初回は権限の承認を求められる → 「詳細」→「(安全でないページ)に移動」→ 許可
  （自分が作った自分のスクリプトなので問題ない）
- 実行ログに `{"ok":true}` が出る
- スプレッドシートに 1 行増える
- `NOTIFY_EMAIL` 宛にメールが 2 通届く（通知＋自動返信のテスト）

ここまで通らない場合、この先のデプロイをしても動かない。ログのエラーを先に潰す。

## 5. ウェブアプリとしてデプロイする

右上の **デプロイ → 新しいデプロイ**

| 項目 | 設定 |
|---|---|
| 種類 | **ウェブアプリ** |
| 説明 | `contact form v1` など任意 |
| 次のユーザーとして実行 | **自分**（＝スプレッドシートとメールの権限で動く） |
| アクセスできるユーザー | **全員** |

> 「アクセスできるユーザー: 全員」でないと、サイトの訪問者から送信できない。
> このスクリプトは書き込み専用で、シートの内容を読み出して返す口はないので、
> URL が知られても保存済みの問い合わせが漏れることはない。

デプロイ後に表示される **ウェブアプリの URL** を控える。

```
https://script.google.com/macros/s/AKfycb.../exec
```

## 6. サイトに設定する

`public/assets/js/config.js` を開き、控えた URL を貼る。

```js
window.GKWORK_CONFIG = {
  GAS_ENDPOINT: "https://script.google.com/macros/s/AKfycb.../exec",
  FALLBACK_EMAIL: "info@gk-work.jp",
  FALLBACK_TEL: "050-3590-0212"
};
```

デプロイし直して、公開サイトのフォームから実際に 1 件送って確認する。

---

## コードを直したとき

エディタで保存しただけでは公開中の URL には反映されない。

**デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ**

この手順なら URL は変わらない。「新しいデプロイ」を選ぶと URL が変わり、
`config.js` の貼り替えが必要になるので注意。

## 制限と運用

| 項目 | 無料 Google アカウント |
|---|---|
| メール送信 | 100 通 / 日 |
| スクリプト実行時間 | 6 分 / 回（このスクリプトは 1 秒程度） |
| 保存件数 | スプレッドシートの上限（1,000 万セル）まで実質無制限 |

1 送信あたりメール 2 通なので、1 日 50 件までは無料枠で収まる。
Google Workspace アカウントなら 1,500 通 / 日。

## スパム対策

- フォームに人間には見えない `website` フィールドを置いてある。
  ここが埋まっている送信は bot とみなし、`{"ok":true}` を返して保存せず捨てる。
- 必須項目とメール形式はクライアントと GAS の両方で検証している
  （ブラウザ側の検証は迂回できるため）。
- 大量送信が実際に来るようになったら、`doPost` の先頭で
  `CacheService` を使った同一 IP のレート制限、または reCAPTCHA の追加を検討する。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 「送信できませんでした」と出る | デプロイの「アクセスできるユーザー」が **全員** になっているか確認 |
| 同上 / コンソールに CORS エラー | 「新しいデプロイ」で URL が変わっている。`config.js` を貼り直す |
| `{"ok":false,"error":"スクリプトプロパティ ... が未設定です"}` | 手順 3 のプロパティ名の綴りを確認 |
| シートには入るがメールが来ない | 1 日 100 通の上限、または迷惑メールフォルダを確認 |
| 何も起きない | Apps Script の **実行数** 画面でエラーログを確認 |
